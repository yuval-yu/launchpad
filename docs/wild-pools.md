# 野池：别人拿我们的币另建的池

**野池** = 包含我们某个发射币、但不是我们毕业流程建出来的 Uniswap v4 池。这一页讲清它从哪来、现在各环节怎么对待它、
不管会出什么事、我们建议怎么办。结论先行：

- **后端（已定）**：币价、K 线、流动性、成交量只认**我们的池**；扫链发 Swap 消息前必须按池过滤（[第 11 页](/gap)已提给扫链）。
- **前端下单（待拍板，Q8）**：毕业后的币建议**默认直连我们的池**，0x 只留给 gasless 与跨资产这两种情况。
- **待验证（Q9）**：0x 在 Robinhood Chain 上到底走不走我们的 Hook 池，dev 上询一次价就知道。

## 野池从哪来

三件事合在一起，野池一定会出现，只是早晚：

1. **v4 建池无许可。** 整条链只有一个 `PoolManager`，任何人都能拿任意两个币、任意费率、任意 hook（或不挂 hook）建池。
2. **发射币没有转账限制。** `LaunchToken` 是标准 ERC-20（`ERC20Upgradeable` + Burnable + Permit），没有重写转账钩子。
   所以**不用等毕业**：有人在曲线上买到币，当场就能建一个野池。
3. **有人有动机这么做。** 我们的池 LP 费率是 0（`LaunchDefaults.V4_POOL_FEE = 0`），费用全由 `GraduatedPoolHook` 在每笔 swap 之后收：
   基础费（上限 10%）+ 创作者税，两者合计上限 20%（`FeePolicyLimits`）。一个不挂 hook、收 0.05% 的野池，对小额单的成交价天然比我们的池好。
   币做大之后，做市的人建野池吃这部分价差是顺理成章的。

**我们的池**是唯一确定的：`GraduatedPoolHook` 只允许我们的 `V4GraduationReceiver` 用它建池（别人调用会 `UnauthorizedPoolInitializer`），
一个币只注册一次（`AlreadyRegistered`），建好后发 `PoolRegistered(poolId, token, quoteAsset)`，全区间流动性交给 `LiquidityLocker` 永久锁定。
所以「是不是我们的池」有两个等价、都可靠的判据：`poolId` 等于该币 `PoolRegistered` 里的那个；或者池的 `hooks` 是我们的 Hook 地址。

## 现状：各环节现在怎么对待野池

| 环节 | 现状 | 有没有问题 |
|---|---|---|
| **扫链：Swap** | 订阅的是 `PoolManager` 的全部 Swap；过滤条件是「两侧至少有一个是发射币」（`swap.ts:40`、`initialize.ts:28`），**野池全部通过**。目前 Swap 还没发 Kafka | **有**。一旦按现在的条件发出来，野池成交就进了我们的库。[第 11 页](/gap)已要求收紧为 `poolId` 匹配 |
| **扫链：Transfer** | 按发币动态注册 `LaunchToken`，只收发射币自己的转账，不分池 | 没有。野池里买到的币照样记进余额 |
| **Java** | Swap handler 还没写（工单 21）。设计上默认「成交的另一侧就是该币的配对资产」，不校验池 | 依赖扫链过滤；Java 不设第二道防线（既定：链上语义归扫链） |
| **前端下单** | 合约给了曲线阶段的完整入口（`TradeRouter` / 直调曲线），**毕业后没有合约入口**。后端为前端透传了 **0x** 的 Swap API 与 gasless 接口；前端对毕业币实际怎么下单，本页没有核对 | **待定**。如果走 0x：它按最优价路由，可能走野池，见下 |

## 不管会出什么事

### 一、野池的 Swap 进了我们的数据（扫链不过滤）

| 后果 | 为什么 |
|---|---|
| **币价、市值、K 线可以被低成本操纵** | 币行的当前价是「每笔成交直接 set」。建一个只放几分钱流动性的野池，用离谱的价 swap 一笔，这个币的价、市值就跳过去，K 线多一根针 |
| **流动性被覆盖** | `liquidity_quote` 同样是 set 型，野池一成交就变成野池的 TVL |
| **成交量可以刷** | 野池不挂我们的 Hook，没有基础费和创作者税，自己和自己对倒几乎零成本；「成交量」排序、24h 量、协议日成交额全被带偏 |
| **金额直接算错，且不报错** | Java 按该币配对资产的精度与美元价处理 `quoteAmount`。野池另一侧可以是任何币，数量级和价格全错 |
| **认币有歧义** | 发射币 A / 发射币 B 的池，`payload.token.token` 填哪个都不对 |

这一组是**数据正确性**问题，必须堵死，没有商量余地。

### 二、用户的单被路由到野池（前端走聚合器）

扫链按池过滤之后，野池里的成交我们看不到。这时：

| 数据 | 影响 |
|---|---|
| 余额、持有者、持有人数 | **不受影响**。来自 Transfer，不分池 |
| 币价、K 线、流动性、成交量 | 不含这笔。**符合预期** |
| 活动 | **缺这一笔** |
| 持仓与盈亏 | 这笔买入不进成本，效果等同「转入」——口径里本来就有这一条（转入、空投不进成本，持仓与链上余额可以不同）。数不会错，只是不完整 |
| **平台与创作者收入** | **这笔收不到基础费和创作者税。** 野池不经过我们的 Hook。这是商业问题，比漏几笔活动严重 |
| 用户体验 | 页面展示的是我们池的价，实际成交在野池，两个价不一样 |

这一组是**完整性与收入**问题，取决于前端怎么下单。

### 三、0x 可能根本不走我们的池（未验证）

聚合器对带 hook 的 v4 池普遍谨慎（hook 可以是恶意合约），通常要逐个加白名单才会路由。如果 0x 不认我们的 Hook，
那么用户经 0x 交易一个已毕业的币，**只可能成交在野池，或者干脆没有报价**。0x 也没法被限制成「只走某一个池」——
它的 `excludedSources` 只能整类排除流动性来源，不能指定池。这一条我们没有数据，见 Q9。

## 业内怎么做

两个问题，两种做法，分开看：

**「这个币值多少钱」——只认权威池，或设流动性门槛。**
发射台（pump.fun、four.meme、Clanker、Virtuals、Zora）只看自己毕业时建的那个池。行情站（DexScreener、GeckoTerminal、Birdeye）按池分开画 K 线，
币级别的价取流动性最深的池，低于门槛的池直接忽略。Uniswap 官方 subgraph 取锁仓最多且超过最低门槛的白名单池——
扫链同学搬来的 `findNativePerToken`、`minimumNativeLocked`、1000 倍失衡保护就是这一套，那段长注释讲的正是「几乎没有流动性的池拉出离谱价」的事故。
**没有人用任意池的最后一笔成交定价。**

**「这个用户做了什么」——看钱包在整笔交易里的净余额变化，不看池。**
GMGN、Birdeye 钱包页、Zerion、DeBank 这类产品不依赖池的 Swap 事件：本币净流入、配对资产净流出，就是一笔买入，价 = 两者相除。
走哪个池、聚合器怎么拆单都能覆盖。我们[第 3 页](/envio)的「按整笔交易的 Transfer 净流量认交易者」是同一个思路。

**发射台的下单方式：直连自己的池，不接聚合器。** pump.fun 直连自家 AMM，four.meme 直连 Pancake 路由，Clanker / Zora 直连 Uniswap 路由加自己的 PoolKey。
要全网最优价的用户自己会去用聚合器，那是他们的选择。

## 推荐方案

### 后端：只认我们的池（已定，不变）

1. **扫链在发 Swap 消息前按池过滤**：`发射币.poolId === event.params.id`（或池的 `hooks` = 我们的 Hook）。野池的数据他自己的库里想留就留。
2. 币价、K 线、流动性、累计成交额、24h 量、协议日统计**只由我们池的成交推进**。
3. 余额、持有者不变，继续不分池。

### 前端：毕业后的币默认直连我们的池（待拍板，Q8）

| 阶段 | 报价 | 下单 |
|---|---|---|
| 曲线 | `Quoter.quoteBuy` / `quoteBuyBounds` / `quoteSell` | 买：`TradeRouter.buy`（配对资产）、`buyWithUniswap`（其它资产）、`launchAndBuy`；卖：直调该币的 `BondingCurve` |
| 毕业后 | Uniswap `V4Quoter.quoteExactInputSingle(poolKey, …)`（模拟真实 swap，Hook 收的费已含在内） | Universal Router `execute`：一条 `V4_SWAP`，动作 `SWAP_EXACT_IN_SINGLE` → `SETTLE_ALL` → `TAKE_ALL`；ERC-20 走 Permit2；`amountOutMinimum` + `deadline` 保护 |

PoolKey 五个字段前端都拿得到、不需要发现：发射币与配对资产（按地址排序）、`fee = 0`、该币发币事件里的 `tickSpacing`、我们的 Hook 地址。
Universal Router 在这条链上已经有（`TradeRouter` 部署时绑定了它）；`V4Quoter` 的地址要前端确认。

这样做的好处：展示价 = 成交价；每笔都收得到基础费与创作者税；每笔成交扫链都看得到，活动与持仓完整；不依赖 0x 是否支持这条链和我们的 Hook。

**0x 保留给两种情况**，并接受这部分成交落在野池时活动不完整：

- **gasless**：用户钱包里没有 ETH 付 gas。直连做不到，除非自建中继 / paymaster。
- **跨资产**：用户拿的不是该币的配对资产。Universal Router 也能多跳，但第一跳走哪个池要有人算。

### 以后（不是现在）：把野池成交记成另一类

如果验证下来野池成交占比不小，再加一类成交：场所标 `OTHER_POOL`，用净流量法记，**只进活动与持仓，永远不碰币价、K 线、流动性、成交量**，
且只在另一侧恰好是该币的配对资产时才记（否则没法估值）。这是纯增量，不影响现在的表和消息，**现在不预留**。
